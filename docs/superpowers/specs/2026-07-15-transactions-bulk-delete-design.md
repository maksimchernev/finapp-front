# Массовое удаление транзакций

## Цель

Добавить на страницу всех операций отдельный режим выбора, в котором пользователь может отметить несколько загруженных транзакций и удалить их после явного подтверждения.

## Интерфейс

- В шапке страницы появляется кнопка «Изменить».
- После входа в режим выбора кнопка меняется на «Готово», у карточек появляются чекбоксы, а над списком — чекбокс «Выбрать все».
- Нажатие на карточку в режиме выбора переключает ее чекбокс и не открывает форму редактирования.
- «Выбрать все» выбирает все транзакции, которые сейчас загружены на странице. Повторное нажатие снимает выбор со всех.
- Внизу экрана отображается закрепленная кнопка «Удалить (N)». Пока ничего не выбрано, она недоступна.
- Выход через «Готово» очищает текущее выделение.

## Подтверждение и удаление

Нажатие «Удалить (N)» открывает диалог: «Удалить N транзакций? Это действие нельзя отменить». Отмена закрывает диалог и сохраняет выделение.

После подтверждения фронтенд вызывает существующее удаление для каждого выбранного идентификатора. На время операции повторные действия блокируются.

- При полном успехе диалог и режим выбора закрываются, выделение очищается, список и связанные финансовые данные отражают удаление.
- При частичной ошибке успешно удаленные транзакции исчезают, не удаленные остаются выбранными, а пользователь видит сообщение об ошибке и может повторить удаление.
- При полной ошибке выделение сохраняется и показывается сообщение об ошибке.

## Границы изменения

Изменение остается внутри frontend. Новый backend endpoint не требуется: используется существующий `DELETE /api/transactions/:id`. Обычный одиночный режим редактирования и удаления транзакции сохраняется без изменений.

## Проверка

Автоматические тесты должны закрепить:

- переключение одного идентификатора;
- выбор и снятие выбора всех загруженных идентификаторов;
- корректное состояние «выбраны все»;
- разделение успешно и неуспешно удаленных идентификаторов при массовой операции;
- наличие ключевых элементов режима выбора и подтверждения на странице.

После реализации запускаются целевые Jest-тесты, затем полная frontend-сборка.
