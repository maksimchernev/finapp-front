# Выключенные по умолчанию OCR-операции

## Цель

Отклонённые операции и переводы должны оставаться в распознанном массиве для ручной проверки, но не должны сохраняться автоматически. Для них OCR-парсер устанавливает `selected: false`; пользователь по-прежнему может включить операцию чекбоксом на review-экране.

## Распознавание блока операции

При разборе строки с суммой парсер просматривает следующие строки её блока. Блок заканчивается перед следующей строкой с суммой или перед следующим заголовком даты. Это связывает статус и описание только с ближайшей операцией и не позволяет словам из соседней операции изменить её выбор.

Операция получает `selected: false`, если в основной строке или последующих строках её блока регистронезависимо найдено хотя бы одно условие:

- фраза `операция отклонена`;
- отдельное слово `перевод` или `переводы`;
- фраза `между своими счетами`.

Словоформы проверяются по границам слова, поэтому случайные вхождения внутри других слов не учитываются. Все остальные операции создаются с текущим значением `selected: true`.

## Границы изменения

- Изменяется только frontend OCR-парсер банковской истории.
- Структура `ParsedTransaction` и review-интерфейс не меняются.
- Отклонённые операции и переводы не удаляются из массива.
- Пользователь может вручную выбрать выключенную операцию.
- Backend и логика batch-сохранения не меняются: они уже сохраняют только элементы с `selected: true`.

## Проверка

Регрессионные тесты подтверждают:

- покупка с последующей строкой `Операция отклонена` присутствует в результате с `selected: false`;
- операция с описанием `Перевод * Основной счёт` имеет `selected: false`;
- операция с описанием `Входящие переводы` имеет `selected: false`;
- обычная покупка остаётся `selected: true`;
- существующий состав, суммы, даты и категории распознанных операций не меняются.
